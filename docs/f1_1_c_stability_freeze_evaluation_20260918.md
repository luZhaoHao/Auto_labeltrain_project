## 2. 三种路径

### 路径 A 冻结优先审查 推荐

只检查发布范围、意外删除、临时产物、敏感信息、硬编码、职责边界和高风险依赖。问题按 P0/P1/P2 分类；P2 记录但不修改，P0/P1 才形成独立最小修复方案。该路径最符合当前稳定性目标。

### 路径 B 主动小范围重构

依据文件大小或重复代码主动拆分 `app.py`、模板或前端脚本。它可能改善长期维护，但会扩大回归面；当前没有故障证据，不建议在稳定冻结前采用。

### 路径 C 全面结构重整

重新划分 UI、训练执行、HPO 和 LLM 模块边界，并清理全部历史兼容入口。收益需要长期验证，风险与当前目标不匹配，本批排除。

### C2 高风险结构审计

- 检查训练启动、停止恢复、运行身份、数据快照、产物收尾和建议展示是否存在重复的权威写入口。

- 只记录能够指向具体文件、触发条件和影响的发现。

### C3 修改决策门槛

只有同时满足以下条件才建议修改：

1. 问题可稳定复现，或能从代码证明会造成数据错误、错误训练、敏感信息泄露、不可恢复状态或发布失败；
2. 严重度为 P0/P1；
3. 可以先写出失败测试或确定性检查；
4. 最小修复不改变已冻结的训练、运行身份、审计和持久化协议；
5. 艾卡审阅独立修复规格后明确批准实施。

P2、代码风格、文件过大、轻微重复和未来扩展便利性只进入风险清单，不在 F1.1-C 修改。
