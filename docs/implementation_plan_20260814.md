## 2. Q1：LLM 可信度 MVP（已完成并合并至 `main`）

**目标**：让“模型可说错、系统不执行错”成为可测试约束。

交付范围：

- 由代码生成版本化事实包，包含来源 ID、值、缺失状态、任务类型和运行绑定。
- 为 LLM 决策建立严格 Schema，限制动作、参数、证据引用和理由字段。
- 确定性校验指标方向、best/final 语义、缺失值、参数类型/范围/依赖、任务适用性和单轮修改数量。
- 校验失败时允许一次结构化纠错；再次失败则记录终态并禁止启动训练。
- 最终改善判断、优胜参数和停止条件继续由代码计算。

首版不做：第二模型复核、知识图谱、多 Agent 辩论、HPO 结果交给 LLM 裁决。

完成记录：Q1.1 事实与证据契约、Q1.2 确定性语义校验、同一事实包的一次纠错、逐次决策审计和审计失败即关闭均已实现。2026-09-02 Codex 独立验收为完整套件 **1484 passed / 2 warnings / 0 skipped**；合法语义决策完成一次最小 Detect CUDA 短训练，三类非法语义决策共六次模型响应均为零命令构造、零训练启动。艾卡已完成线下体验确认，Q1 已通过 GitHub PR #10 合并至 `main`（功能提交 `d6a27f7`，合并提交 `2e930f6`）。语义规则和维护边界见 `llm_tuning_semantic_rules.md`。

## 3. H1：Detect HPO MVP（6–10 人日）

**引擎选择**：产品使用 Optuna TPE，随机搜索作为基线；Ultralytics 遗传调优只做内部基准比较。

首版流程：

1. 用户在直接训练、HPO、LLM 三种策略中选择一种。
2. HPO 创建独立 study，绑定数据快照、模型、目标指标、预算和搜索空间版本。
3. 每个 trial 复用现有训练执行、状态、日志、产物和失败终态。
4. 首版搜索约 6 个高价值参数：`lr0`、`lrf`、`optimizer`、条件化 `momentum`、`weight_decay`、`warmup_epochs`。
5. 按固定 trial 数顺序执行；超时、OOM、用户停止和非法组合形成明确终态。
6. 使用统一指标确定性排名，候选最优参数可再做一次固定配置验证训练。

首版不做：Ray、并行调度、多目标优化、复杂剪枝、自动扩大搜索空间。

验收门槛：TPE 与随机基线均可运行；study 可恢复；失败 trial 不污染优胜结果；同一指标口径可回溯到原始产物；无 LLM 凭据时 HPO 完整可用。

### 5.1 单镜像运行方式

- 只发布一个 `auto-tune` Docker 镜像，并以一个容器运行完整 Studio Web UI。
- F1.2 不实现仅 API 的 Engine 模式；现有内部 HTTP 接口只服务 Studio 页面和本地运行，不作为用户调用入口或外部产品能力。
- 数据集分析、直接训练、HPO、LLM 调优、训练结果分析和模型导出复用现有业务内核。
- 正式 Docker 启动即使用 NVIDIA 运行时申请 GPU；GPU 不可用时明确报错，不发布独立 CPU/CUDA 镜像。
- 数据集、模型、结果和配置通过受控目录或 NAS 挂载；容器中不得固化密钥、业务数据、权重或训练结果。

按一人顺序执行，B–E 名义合计 5–11 个有效研发日；共享事项不可机械相加。Docker Engine、驱动、网络镜像源或权限问题的外部等待，以及艾卡准备截图的时间不计入。B/C 的 GPU 运行依赖宿主机 NVIDIA 环境，D 的 Windows 安装不依赖这些 Docker 条件。

**每批工作流：**Codex 先核对当前规格、计划、工作区与前批验收结论，只下发当前批次给 Claude Code；Claude Code 先写失败测试再实现，运行定向与完整回归，只报告实际改动、命令结果、偏离和风险，不修改权威文档、不提交、不推送；Codex 独立审查代码、复跑测试及必要真实运行，形成“通过/不通过”结论。未通过则按问题清单返修，不跨批。艾卡确认需要人工体验的交付后，Codex 才同步文档并按批准范围整理版本。

**Docker 环境由 Codex 主责，不把宿主机故障转嫁给 Claude Code 改业务逻辑。**截至 2026-09-20，本机 Docker CLI 与 `desktop-linux` context 存在，WSL2 Ubuntu 和 RTX 3060 可见，但 Linux Engine 管道无法连接。B 批开始时先检查 Docker Desktop 运行状态、Engine/context、WSL2、磁盘空间和驱动；环境修复涉及安装、升级、重置或删除数据时先征得艾卡确认。Engine 恢复后先验证 GPU 透传条件，再由 Claude Code 构建/自测镜像，Codex 独立复验。若 Engine 仍不可用，可先完成非容器代码与静态测试，但 B 保持“未验收”，不以模拟结果替代实测。

**批次共用门槛：**宿主机 Python/pytest 固定使用 `D:\Program Files\anaconda3\envs\auto_tune\python.exe`，先记录 `sys.executable` 与版本；新增依赖先列版本、用途和体积并由艾卡确认。测试使用受控临时目录和最小合法数据集，不复制整个项目、不创建包含大文件的工作树。提交前检查 `.gitignore`、待提交文件、凭据/真实配置/数据/权重/产物排除范围及测试证据，只允许推送指定公开仓库。
