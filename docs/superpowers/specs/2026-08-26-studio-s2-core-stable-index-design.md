# Studio S2 Core 稳定索引设计

**日期**：2026-08-26

**状态**：待艾卡审阅

**目标工期**：4–7 人日
**优先级**：稳定性优先，可用闭环优先，高级能力后置

## 1. 决策摘要

S2 第一版只建设 Studio 单机模式真正需要的 SQLite 本地索引：数据集、训练/调优实验、报告和产物可以在应用重启后可靠查询并重新打开。SQLite 是可重建的查询索引，不替代 JSON 审计事实文件，也不复制数据集、权重或训练产物。

多数据集重命名、标签、批量操作、归档清理、高级搜索、统计图表、导入导出和复杂对比页面不作为 S2 Core 验收条件。本批只为这些能力保留稳定的 Repository/Service/API 扩展边界，后续有真实需求时再实现。

## 2. 必做范围

### 2.1 SQLite 基础

- 仅使用 Python 标准库 `sqlite3`，不新增运行依赖。
- 建立 Schema 版本表和按版本顺序执行的迁移机制；迁移在单一事务中完成，失败必须回滚。
- 明确数据库文件位置、连接生命周期、事务边界、外键、`busy_timeout` 和 WAL 策略。
- 首次创建、重复启动和旧版本升级必须幂等。
- 数据库损坏或迁移失败时不得静默覆盖原文件、删除事实文件或伪造空历史；返回稳定错误码并保留诊断信息。

### 2.2 数据集索引

- 记录稳定 `dataset_id`、显示名称、规范化目录、快照身份、校验状态、创建/更新时间和最近使用时间。
- 同一数据集或同一有效快照重复登记时幂等更新，不产生重复记录。
- 索引只保存必要元数据和路径引用，不复制数据集内容。
- 提供列表、详情、登记/刷新和存在性检查的 Service 接口。

### 2.3 实验与结果索引

- 普通训练和自动调优共用实验记录，使用 S1.5 的 `run_id` 作为唯一运行关联键。
- 保存运行类型、数据集关联、状态、阶段、模型/任务摘要、开始/结束时间、关键指标摘要，以及报告和产物的相对或受控绝对路径引用。
- 训练/调优进入终态时写入或更新索引；重复终态回调必须幂等。
- JSON 审计、运行状态和报告继续作为事实文件；SQLite 只保存可查询投影和引用。

### 2.4 旧记录只读迁移

- 提供显式、可重复执行的扫描/导入 Service，读取现有合法 JSON 历史并写入 SQLite。
- 迁移以来源身份和内容摘要去重；单个损坏文件记录错误并跳过，不阻断其他合法记录。
- 不改写、不移动、不删除旧 JSON、训练目录或报告。

### 2.5 最小 API 与 UI

- 提供数据集列表/详情、实验列表/详情和旧记录导入状态 API。
- 支持少量稳定筛选：数据集、运行类型、状态和时间倒序。
- UI 只需展示基础列表、筛选、详情和打开既有报告/产物入口；不做复杂管理工作台。
- 空库、损坏库、迁移部分失败和引用文件缺失必须给出诚实、可恢复的提示。

## 3. 稳定接口边界

业务代码不得直接散落 SQL。S2 Core 使用三层边界：

1. `storage`：连接、事务、Schema 版本和迁移。
2. `repository`：数据集、实验和迁移记录的参数化 CRUD/查询。
3. `service`：幂等登记、事实文件投影、路径约束、错误映射和 API 使用场景。

后续标签、归档、批量操作、复杂对比和统计只通过新增 Repository/Service 方法扩展，不要求调用方依赖表结构或直接拼接 SQL。首版不为未实现功能返回虚假成功；未开放的 API 不注册，预留的内部接口可以明确抛出 `NotImplementedError` 或稳定的“功能未启用”错误。

## 4. 建议 Schema v1

- `schema_migrations`：`version`、`applied_at`、`checksum`。
- `datasets`：稳定身份、名称、规范化路径、快照身份、校验状态和时间字段。
- `experiments`：`run_id`、运行类型、数据集外键、状态/阶段、模型与任务摘要、时间字段和关键指标 JSON 摘要。
- `artifacts`：实验外键、类型、受控路径、存在性和时间字段。
- `legacy_imports`：来源身份、内容摘要、导入结果、错误码和时间字段。

枚举值和 JSON 摘要必须通过领域模型校验；未知旧值以兼容投影保存或标记，不因单条旧记录阻断数据库启动。

## 5. 明确后置功能

- 数据集重命名、业务标签、收藏、批量编辑和批量删除；
- 自动归档、空间回收和训练产物生命周期管理；
- 全文搜索、组合查询、保存筛选和复杂分页优化；
- 多实验图表、指标聚合、排行榜和统计看板；
- CSV/Excel/外部数据库导入导出；
- 多用户权限、远程数据库、云同步和 Cloud 数据模型；
- 自动修复或删除损坏数据库、事实文件和引用产物。

## 6. 失败与恢复原则

- SQLite 写入失败不能改变训练真实终态，也不能让 UI 把失败伪装成成功；状态事实仍由 S1.5 和 JSON 审计保留。
- 数据库不可用时，查询 API 返回稳定错误和恢复建议；不自动创建一个空库覆盖原库。
- 迁移前创建受控备份；备份数量和空间必须有上限，数据库文件不得包含数据集二进制、模型权重或日志全文。
- 文件引用缺失只标记 `missing`，不删除实验记录。
- 所有 SQL 使用参数化语句；路径进入索引前复用 S1.4 的目录安全约束或等价校验。

## 7. 验收标准

- 空目录首次启动、重复启动和版本升级均成功且 Schema 一致。
- 普通训练与调优完成后各产生一条可查询实验记录，重放终态不会重复。
- 应用重启后可按数据集、运行类型和状态查询，并打开仍存在的报告/产物。
- 旧 JSON 导入可重复执行；合法记录不重复，损坏记录隔离并报告。
- 数据库锁、写入失败、损坏库、迁移失败和引用缺失均有确定性测试。
- S1.5 运行、停止、断线重连和真实终态不因 SQLite 故障而退化。
- 完整自动化测试通过；至少执行一次最小合法数据集的短训练，验证终态和索引一致。
- Git 提交不包含数据库实例、备份、数据集、权重、训练产物、日志或本机业务路径。

## 8. 实施顺序与工期

1. 存储基础、Schema v1、迁移和故障保护：1–2 人日。
2. 数据集与实验 Repository/Service、幂等写入：1–2 人日。
3. 旧 JSON 只读导入、最小 API/UI：1–2 人日。
4. 独立回归、短训练和边界修复：1 人日。

总计 4–7 人日。若稳定性门禁尚未通过，不用高级 UI 或附加管理功能换取表面进度。
