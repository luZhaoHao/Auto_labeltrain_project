# 双语操作型 README 设计

**日期：** 2026-08-14  
**状态：** 用户已确认内容方向

## 1. 目标读者

根目录 README 面向第一次接触项目的操作人员、测试人员和技术负责人。默认假设读者了解基本命令行操作，但不了解 Module A/B/C、Guardrails 或调优审计等内部概念。

## 2. 文件与语言切换

- `README.md`：中文默认入口。
- `README_EN.md`：英文入口。
- 两份文件首屏使用相对链接互相切换语言。
- 两份文件章节、命令、限制和版本状态保持一致。

## 3. 信息顺序

README 按操作人员完成一次任务的顺序组织：

1. 项目能解决什么问题。
2. 当前可用能力与适用边界。
3. 使用前准备。
4. Windows 安装与配置。
5. 选择数据集目录并运行分析。
6. 普通训练与实时监控。
7. 训练诊断和四项 KPI。
8. 自动调优、安全护栏和审计。
9. 统一训练历史与结果查看。
10. 常见问题和错误处理。
11. 开发者测试命令。
12. 项目结构、当前限制和路线图。
13. GitHub 文件安全边界。

技术架构放在操作流程之后，避免内部实现阻碍首次使用。

## 4. 当前版本事实

README 必须明确：

- 当前验证平台为 Windows、Python 3.10。
- 当前稳定任务为 Ultralytics YOLOv8 detection。
- 数据接入的推荐方式是选择本地/服务器目录，不以 ZIP 上传作为主流程。
- LLM 当前只建议超参数；候选值经过 Schema、白名单和 Guardrails 后才能训练。
- 普通训练与自动调优共享 Module B 收尾、KPI 和统一实验历史。
- 自动调优具有原子审计记录，保存建议、护栏、实际命令和 before/after/delta。
- 当前完整测试证据为 `160 passed`，两条既有 sklearn PCA warning。
- 模型结构解析与结构自调整、YOLO11/26、Linux 和在线多人平台属于后续阶段。

## 5. 安装与配置

- 优先给出 `setup.bat` / `start_app.bat` / `run_tests.bat` 的 Windows 操作。
- 同时给出 Conda 命令行等价操作。
- 配置从 `auto_tune/config.template.yaml` 复制为 `auto_tune/config.yaml`。
- 示例只使用占位 API Key，不复制真实配置。
- 明确 `config.yaml`、`qwen.txt`、数据集、权重、日志和训练产物不应提交 GitHub。

## 6. 图片策略

当前工程没有适合公开 README 的脱敏 UI 截图。`docs/_render_leader_roadmap*` 是计划书整页渲染图，不用于 README，因为它们体积较大、信息密度高且不是操作界面。

当前版本使用 GitHub 原生 Mermaid 展示操作流程和模块关系，不新增二进制图片。未来若加入产品截图，应满足：

- 放置于 `docs/images/`；
- 不包含本机绝对路径、数据集名称、API Key 或其他敏感信息；
- 中文和英文 README 复用同一组图片；
- 每张图片都直接帮助完成一个操作步骤。

## 7. 写作规则

- 先给动作，再解释概念。
- 命令必须可复制执行。
- 不宣称尚未完成的功能。
- 不展示真实业务数据、指标截图或本地绝对路径。
- 中英文术语保持一一对应。
- 主 README 控制在完整但可扫描的长度，详细研发计划链接到 `docs/`。

## 8. 验收

1. 两份 README 语言链接互通。
2. Markdown 代码围栏与 Mermaid 语法完整。
3. 文件内相对链接存在。
4. 启动、测试和配置命令与当前仓库一致。
5. 两份文档的能力、限制和测试计数一致。
6. 不包含疑似 API Key、本机绝对路径或训练产物链接。
7. 不引用计划书渲染图或其他待排除文件。
