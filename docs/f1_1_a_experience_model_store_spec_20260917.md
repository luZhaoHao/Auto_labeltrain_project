# F1.1-A 体验优化与受控权重库规格

日期：2026-09-17
状态：艾卡已于 2026-09-17 确认；实施计划见 `docs/superpowers/plans/2026-09-17-f1-1-a-experience-model-store.md`
前置基线：H1.3 已验收，提交 `2ce647d`；文档整理提交 `386504c`

## 1. 目标

F1.1-A 只处理当前已确认的体验问题和权重管理需求，不扩大主体训练能力：

1. 修复“大模型调优”提交 `mode=None` 后返回 `INVALID_MODE` 的阻断问题。
2. 将各模式的主操作按钮放回对应配置区末尾，避免配置和启动入口相距过远。
3. 建立统一、受控的本地权重存储目录和上传入口。
4. 直接训练与 HPO 可从受控权重库选择初始权重；大模型调优继续继承参考运行的权重。
5. 丰富 HPO 动态进度，但不开发实时 loss/mAP 曲线或系统资源图表。

本批完成并独立验收后，才启动 F1.1-B“LLM 准确率专项”。F1.1-C 在 A、B 完成后重新评估，不自动启动。

## 2. 已确认根因

`single_page.html` 中 `tuningModeSelect` 被移动到 `tuningForm` 之外，但没有通过 `form="tuningForm"` 与表单关联。提交处理使用 `new FormData(tuningForm)`，因此得到 `mode=null`，随后向 `/tuning/start` 发送 `"mode": null`。后端保留严格白名单并正确返回：

```text
[INVALID_MODE] 未知训练模式: None
```

修复必须发生在表单字段关联的来源处，不能通过放宽后端校验、把 `None` 猜成 `full`，或静默选择某个模式掩盖问题。

## 3. 冻结产品语义

### 3.1 权重上传与选择

- 上传权重只负责把操作人员提供的 `.pt` 文件保存到统一受控模型目录。
- 默认受控目录为项目根下的 `models/weights/`；该目录中的权重不进入 Git。
- 服务器部署时可直接将权重传输到该目录，也可从 Studio 上传。
- F1.1-A 不自动访问网络、不自动下载 Ultralytics 权重、不引入远端模型仓库。
- 项目根目录中已经存在的少量 `.pt` 作为遗留兼容来源继续可读；新上传文件统一进入受控目录。
- 初始权重选择器不再混入 `detect/trainN/weights/` 下的大量训练产物。
- 最终训练的 `best.pt`、`last.pt` 继续通过训练历史、实验详情和结果入口访问，不自动加入初始权重库。

三条训练路线的规则：

| 路线 | 权重规则 |
|---|---|
| 直接训练 | 可从受控权重库选择初始权重 |
| HPO | 可从受控权重库选择不同初始权重，并把所选文件哈希冻结到研究绑定 |
| 大模型调优 | 不提供独立权重选择器；必须继承参考运行 `args.yaml` 中已经使用的权重 |

大模型调优不得用新权重训练却继续把旧参考运行指标当作基线。本批不实现“自动补跑新权重基线”，也不允许客户端覆盖参考运行的模型字段。

### 3.2 建议预置权重

仅建议运维或安装阶段预放少量常用文件，例如 `yolov8n.pt`、`yolov8s.pt`。F1.1-A 不把二进制权重提交仓库；文件实际不存在时不得显示为可用，也不得在选择后才触发隐式下载。

## 4. 受控权重库设计

新增单一职责的权重库服务，负责列举、上传、解析和文件事实投影；页面与训练入口不得各自重新扫描磁盘。

### 4.1 列表投影

列表仅返回界面需要的安全字段：

- 受控模型标识；
- 文件名；
- 大小；
- SHA-256；
- 来源类型（受控权重库或遗留项目根目录）；
- 是否可用。

客户端不得提交任意服务器保存路径。服务端根据受控模型标识重新解析真实文件，并在训练提交边界再次校验文件仍存在、仍是普通 `.pt` 文件且未被替换。

### 4.2 上传规则

- 只接受单个 `.pt` 文件。
- 文件名必须取 basename；拒绝绝对路径、目录分隔符、`..`、控制字符和空文件名。
- 使用受控大小上限；超限时停止读取并删除临时文件。
- 先流式写入同目录临时文件，同时计算 SHA-256，再执行 flush/fsync 和原子落盘。
- 拒绝符号链接、junction、reparse point 和非普通文件目标。
- 同名同哈希返回“已存在”；同名不同哈希返回稳定冲突错误，绝不静默覆盖。
- 上传阶段不反序列化、不加载、不执行 `.pt` 内容。
- 失败不得留下半文件、临时文件、索引假记录或被选择的无效选项。

### 4.3 路径兼容

HPO 既有研究已经冻结绝对模型路径和哈希，旧记录仍按原契约读取。新研究通过受控模型标识选择文件后，服务端继续冻结最终规范化路径、字节数、修改时间和 SHA-256；不得改绑旧研究。

## 5. 主操作按钮与模式提交

### 5.1 模式字段

- `tuningModeSelect` 必须成为 `tuningForm` 的正式表单关联控件。
- 实际渲染页上的 `FormData(tuningForm).get("mode")` 必须分别得到 `dry_run`、`keep_params`、`hpo`、`full`。
- `hpo` 只能进入 HPO 创建流程；其他三个合法值进入 `/tuning/start`。
- 后端继续拒绝 `null`、空值、未知字符串及把 HPO 发到 LLM 接口的请求。

### 5.2 按钮位置

- 大模型调优：主按钮位于“评估模式”下方，即艾卡截图红框位置。
- HPO：`创建并开始调优` 位于“新建搜索草稿”配置底部、当前任务区域之前。
- 干运行与按原参数训练：主按钮位于各自可见配置区域末尾。
- 同一模式只能有一个可见主操作；不得复制按钮、重复 DOM ID 或生成浮层。
- 提交期间按钮禁用并防重复提交；请求失败后恢复；任务接受后由权威运行状态决定停止、恢复和后续操作。

实现可使用单一按钮在预置 action host 之间移动，或使用既有两个不同语义按钮分别放在 LLM/普通训练与 HPO 配置区；无论采用哪种方式，提交逻辑和测试契约必须只有一份。

## 6. HPO 动态进度

保留现有百分比进度条，并增加以下只读投影：

1. 按预算顺序展示每个试验的状态轨道：等待、运行、成功、失败、取消/中断。
2. 当前执行试验编号；没有权威当前项时显示 `—`。
3. 成功、失败、取消/中断、运行中和剩余数量。
4. 当前最佳试验、评价方式和综合分数。
5. 最近三条关键事件，例如试验启动、试验终结、最佳结果更新、研究暂停或完成。
6. 完成、暂停、失败、阻断状态的明确终态文案。

所有内容必须复用既有轮询响应或服务端持久事实：

- 不增加第二套轮询器；
- 不以浏览器计时器推测进度；
- 不因重复/乱序响应重复追加事件；
- 切换研究后旧研究响应不得污染当前研究；
- 刷新页面后可从持久事实恢复同一展示；
- 不开发实时 loss/mAP 曲线、GPU/显存/利用率/温度图表。

## 7. 错误与安全投影

新增错误必须使用稳定错误码和可操作中文提示，至少覆盖：

- 文件类型不合法；
- 文件名不合法；
- 文件为空或超限；
- 同名冲突；
- 临时写入或原子落盘失败；
- 受控权重库不可用；
- 权重在提交前被删除或替换；
- 路径安全校验失败。

响应和页面不得泄露完整服务端业务路径、堆栈、命令、配置或凭据。上传失败、列表失败和训练提交失败应彼此隔离，不能清空此前合法权重或破坏正在运行的任务。

## 8. 测试要求

所有业务改动先写 RED 测试，再最小实现转 GREEN。

### 8.1 模式与按钮

- 真实模板中模式选择器在表单外仍能被 `FormData` 正确收集。
- 四种模式分别提交正确的完整值。
- 大模型调优不再发送 `null`。
- HPO 不调用 `/tuning/start`，大模型调优不调用 HPO 创建接口。
- 各模式按钮位于指定 action host，页面不存在重复 ID。
- pending 时重复点击只产生一次请求。

### 8.2 权重库

- 合法 `.pt` 上传、列举、刷新和三条路线的可见性规则。
- 直接训练与 HPO 可绑定受控权重；大模型调优无独立权重覆盖字段。
- 项目根已有初始权重兼容可读；训练产物不进入初始权重列表。
- 路径穿越、绝对文件名、错误扩展名、空文件、超限、同名异内容、链接/reparse、并发冲突和写盘失败均无残留。
- 上传接口不反序列化权重，不执行网络访问。
- 文件上传后被替换时，训练提交边界拒绝启动。

### 8.3 HPO 进度

- READY、RUNNING、PAUSED、INTERRUPTED、BLOCKED、COMPLETED、FAILED 的轨道与文案。
- 重复轮询幂等；乱序和旧研究响应被丢弃。
- 当前试验、计数、最佳结果和最近事件准确收敛。
- 刷新后由持久事实重建，不产生第二个轮询器。

### 8.4 回归范围

至少运行：

- HPO UI behavior/rework/lifecycle/API/formal training；
- 普通训练 UI 与运行状态重连；
- 上传与路径安全；
- Agent tuning loop、decision、guardrails；
- 完整测试套件；
- `pip check`；
- 修改过的 JavaScript `node --check`；
- 模板重复 DOM ID 和本批文件冲突标记/行尾空白检查。

Codex 独立进行真实浏览器检查；如权重选择影响训练启动，则使用最小合法数据集完成必要的短 GPU 验证。不得把自动化结果冒充浏览器或真实训练验收。

## 9. 不在 F1.1-A 范围

- LLM 准确率问题的实际修复（属于 F1.1-B）；
- 大模型调优任意切换权重或自动补跑基线；
- 网络模型商店、自动下载、远端同步和模型版本管理；
- 删除已上传权重、覆盖权重、批量导入和权限系统；
- HPO 实时 loss/mAP 曲线；
- GPU、显存、利用率或温度图表；
- 大规模拆分 `app.py`、`single_page.html` 或全局重构；
- Windows、Docker 和 API 交付适配。

## 10. 验收门槛

F1.1-A 只有同时满足以下条件才可通过：

1. 大模型调优模式能正确提交并进入原有 LLM 流程。
2. 主操作按钮位于已确认区域，四模式均可发现且无重复入口。
3. 上传权重安全进入受控目录，失败无残留。
4. 直接训练和 HPO 可选择受控权重；LLM 继承参考运行权重且无法覆盖。
5. HPO 进度能动态展示试验轨道、当前试验、当前最佳与最近事件。
6. 不新增图表或系统资源监控，不发生范围外重构。
7. 定向测试、完整套件、静态检查和必要真实验证通过。
8. Claude Code 不修改项目文档、不提交、不推送；Codex 独立验收后再回写文档和处理 Git。
