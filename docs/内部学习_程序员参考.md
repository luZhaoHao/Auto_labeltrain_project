```
    │   └── run_comparator → 多轮次对比取最佳
    ├── Stage 2: LLM 诊断 (DeepSeek, ~200 tokens)
    │   └── 用自然语言描述训练质量、问题定位、改进建议
    ├── Stage 3: 视觉分析 (Qwen-VL, ~500 tokens)
    │   ├── 混淆矩阵分析 — 哪些类别容易混淆
    │   └── 错误裁剪分析 — 模型犯错的具体样本特征
    └── 输出 train_*_report.json
    │
    ▼
【Module C】run_tuning_loop()  ← 闭环
    ├── Step 1: Perception → 聚合 Module A+B 报告
    ├── Step 2: Decision → LLM 决策调参建议
    ├── Step 3: Guardrails → 校验+钳制参数
    ├── Step 4: Execute → 修改参数 + 启动 YOLO 训练
    ├── Step 5: Probe Monitor → 前 N 个 epoch 监控
    │   ├── 趋势良好 → CONTINUE (继续训练到底)
    │   ├── 趋势差   → ABORT (浪费资源，立即停止)
    │   └── 不确定   → RETRY (调参后重试)
    └── 自动分析 (auto_analyze) → 回到 Step 1
```

## 2. 关键实现详解

### 2.1 Module A: 数据集分析器

**核心文件**: [analyzer.py](../auto_tune/modules/dataset_analyzer/analyzer.py)

`analyze_dataset()` 函数是入口，接收数据集目录和配置，返回完整分析报告。

**关键设计点**：

**两种目录布局支持**：
```python
# 结构化布局: dataset/images/train/ + dataset/labels/train/
# 平铺布局: dataset/*.jpg + dataset/*.txt
def _detect_layout(dataset_dir):
    if os.path.isdir(os.path.join(dataset_dir, "images", "train")):
        return os.path.join(dataset_dir, "images", "train"), False  # 结构化
    return dataset_dir, True  # 平铺
```

**采样分析优化**：
- 图像质量分析使用随机采样（默认 500 张），避免对大数据集全量处理
- 特征聚类同样采样（默认 200 张）
- 用 `numpy.random.default_rng()` 保证可复现

**综合质量评分公式**：
```python
quality_score = 1.0 - (
    blur_ratio * 0.15 +          # 模糊率权重
    under_exposure_ratio * 0.15 + # 欠曝率权重
    over_exposure_ratio * 0.15 +  # 过曝率权重
    imbalance_penalty * 0.25      # 类别不均衡惩罚
)
```

### 2.2 Module B: 训练结果分析器

**核心文件**: [analyzer.py](../auto_tune/modules/train_analyzer/analyzer.py)

三阶段分析的编排模式值得学习。

**Stage 1 — Python 规则分析（无 LLM 成本）**：

`results_parser.py` 中的 `load_training_run()` 解析 YOLO 的 `results.csv`，提取每轮指标：
```python
# 关键字段提取
best_epoch = df["metrics/mAP50(B)"].idxmax()  # 最佳 epoch
final_metrics = df.iloc[-1].to_dict()          # 最终指标
```

`curve_analysis.py` 用线性回归计算曲线斜率判断趋势：
```python
from scipy import stats
slope, intercept, r_value, p_value, std_err = stats.linregress(epochs, values)
# slope > 0.01 → 上升趋势, slope < -0.01 → 下降趋势, 其余 → 平稳
```

`issue_detector.py` 检测多种训练问题：
```python
# 过拟合检测: val_loss 在上升但 train_loss 继续下降
# 欠拟合检测: mAP50 低于阈值且曲线仍在上升（需要更多 epoch）
# 平台期检测: 最近 N 个 epoch 的 mAP50 变化 < 阈值
# 震荡检测: 指标方差过大
```

**Stage 2 — LLM 文本诊断**：

**核心架构**：构建 prompt → 调用 API → 解析结果

```python
def analyze_with_llm(report, config) -> dict:
```

### 2.3 Module C: 自动调优引擎

**核心文件**: [loop.py](../auto_tune/modules/agent_engine/loop.py)

这是项目的核心创新点，面试中最值得展开讲的部分。

**`run_tuning_loop()` 主循环**：

```python
for iteration in range(1, max_retries + 1):
    # Step 1: Perception — 聚合 Module A + B 数据
    perception = build_perception(log_dir=log_dir)
    
    # Step 2: Decision — LLM 决策调参
    decision = decide_hyperparameters(perception, config, prev_changes)
    
    # Step 3: Guardrails — 安全护栏
    guard_result = validate_and_clamp(changes, dataset_info)
    if not guard_result.valid:
        continue  # 跳过本轮
    
    # Step 4: Execute — 启动训练
    proc = launch_training(train_name, args_path, merged)
    
    # Step 5: Probe Monitor — 早期监控
    probe_decision = monitor_training(train_proc, config)
    if probe_decision.verdict == ABORT:
        continue  # 直接跳过
    elif probe_decision.verdict == RETRY:
        continue  # 重试
    
    # 训练完成后自动分析
    if auto_loop:
        continue  # 进入下一轮调优
    break  # 单次模式，直接返回
```

**关键设计模式**：

**1. 回调机制 (Callback Pattern)** — 用于实时日志推送：
```python
run_tuning_loop(
    config,
    on_progress=lambda iteration, msg: print(f"Iter {iteration}: {msg}")
)
```
UI 模式中，`on_progress` 把消息推送到线程安全队列，SSE 端点从队列中消费。

**2. 取消机制 (Event Pattern)** — 用 `threading.Event` 实现：
```python
_cancel_event = threading.Event()
# 主循环每轮开始时检查
if cancel_event and cancel_event.is_set():
    return {"error": "用户取消"}
```

**3. 探针监控 — 状态机**：

```python
class ProbeDecision:
    CONTINUE = "continue"  # 趋势良好，继续训练
    ABORT = "abort"         # 趋势差，终止训练
    RETRY = "retry"         # 不确定，建议调参重试
```

**4. TuningResult 评分公式**：

```python
# 全面模式: 四项指标加权
score = mAP50*0.35 + mAP50_95*0.25 + precision*0.20 + recall*0.20

# 快速模式: 只看 mAP
score = mAP50*0.6 + mAP50_95*0.4
```

### 2.4 Web UI 架构

**核心文件**: [app.py](../auto_tune/ui/app.py)

**FastAPI + SSE 实时流**：

训练日志推送采用 SSE（Server-Sent Events），核心机制：

```python
def on_progress(iteration, message):
    msg_queue.put(json.dumps({"status": "running", "message": message}))

# SSE 端点
async def event_stream():
    yield "data: ...\n\n"  # 初始消息
    future = loop.run_in_executor(None, run)  # 在线程池运行训练
    while True:
        # 非阻塞消费队列消息
        try:
            msg = msg_queue.get_nowait()
            yield f"data: {msg}\n\n"
        except queue.Empty:
            pass
        if future.done():
            yield f"data: {json.dumps({'status': 'done'})}\n\n"
            break
        await asyncio.sleep(0.15)  # 让出事件循环
```

**关键坑点**：
- 不能用 `queue.get(timeout=0.5)`，它会阻塞事件循环，导致 `future.done()` 永远不返回 True
- 用 `get_nowait()` + `await asyncio.sleep(0.15)` 非阻塞轮询

**SSE 数据结构**：
```json
// 运行中
{"status": "running", "message": "Epoch 10: mAP50=0.523", "iteration": 1}
// 完成
{"status": "done", "result": {"best_iteration": 2, "best_metrics": {...}}}
// 取消
{"status": "cancelled", "message": "训练已取消"}
// 错误
{"status": "error", "message": "训练失败..."}
```

**缓存策略**：
```python
_cache = {}  # TTL 缓存，避免每次请求都读磁盘
_CACHE_TTL = 300.0  # 5 分钟

def _cached(key):
    entry = _cache.get(key)
    if entry and time.time() - entry[0] < _CACHE_TTL:
        return entry[1]
    return None
```

## 4. 面试相关知识点

本项目涵盖了多个面试高频考点，按重要程度排列：

### ⭐⭐⭐⭐⭐ 高频考点

**1. SSE 实时流 + 多线程模型**
- 问题：如何实现长时间运行的训练任务 + 实时日志推送？
- 本项目方案：`ThreadPoolExecutor` + `queue.Queue` + `asyncio` 事件循环
- 关键点：为什么 `queue.get(timeout)` 会阻塞事件循环？如何用 `get_nowait() + await sleep()` 解决？

**2. LLM Agent / Function Calling 设计模式**
- 问题：如何让 LLM 做决策并执行动作？
- 本项目方案：Perception → Decision → Guardrails → Execute → Monitor
- 关键点：Guardrails 层为什么重要？LLM 输出不可靠时如何保证安全？

**3. 回调模式 (Callback Pattern)**
- 问题：如何解耦业务逻辑和 UI 层？
- 本项目方案：`on_progress` 回调函数注入
- 关键点：函数作为一等公民（Python）、闭包捕获作用域

**4. 线程安全队列**
- 问题：多线程生产者-消费者模式如何实现？
- 本项目方案：`queue.Queue` + `threading.Event`

### ⭐⭐⭐⭐ 中频考点

**5. 线性回归曲线分析**
- 问题：如何判断训练曲线是否收敛？

- 扩展：为什么要用移动平均窗口？`val_loss_ma_window: 5`

**6. FastAPI 异步编程**
- 问题：FastAPI 中 async/await 的使用场景
- 本项目方案：文件上传用 async，计算密集型任务用线程池

**7. 缓存策略**
- 问题：如何避免重复读磁盘？
- 本项目方案：内存 TTL 缓存，上传/训练完成后失效

**8. 安全护栏设计**
- 问题：LLM 输出不可控时如何保证系统安全？
- 本项目方案：`validate_and_clamp()` 校验参数范围、合理性、冲突检测

## 5. 常见问题与排错

### 5.1 启动问题

**Q**: `conda activate auto_tune` 报错？
**A**: 确保 Conda 已安装且在 PATH 中，或使用 `conda.bat activate auto_tune`

**Q**: 端口被占用？
**A**: 修改 `main.py` 中的 `port` 参数，或杀死占用进程：
```bash
netstat -ano | findstr :8000
taskkill /PID <PID> /F
```

### 5.2 训练问题

**Q**: YOLO 训练命令报错？
**A**: 新版 Ultralytics 需要 `arg=value` 格式（不是 `--arg value`），检查 `executor.py` 和 `app.py` 中的命令构造

**Q**: GPU 显存不足？
**A**: 减小 batch size（默认 16 → 8 或 4），或使用更小的模型（yolov8n.pt）

### 5.3 API 问题

**Q**: LLM API 调用失败？
**A**: 检查 `config.yaml` 中的 API key 是否有效，以及 endpoint URL 是否正确

**Q**: SSE 连接中断？
**A**: 目前不支持断线重连（二期计划）。检查网络是否稳定，训练是否仍在运行

### 5.4 测试问题

**Q**: 测试需要 GPU 吗？
**A**: 不需要。所有测试使用合成数据（numpy 假图片、假 CSV），在 CPU 上即可运行

**Q**: 如何运行全部测试？
```bash
python -m pytest auto_tune\tests -v
```
