# Auto-Tune Studio — controlled Linux container runtime dependencies (F1.2-B).
#
# Scope: only what the Studio needs at runtime inside the container.
#   * every package imported by production code under auto_tune/ (excluding
#     tests and scripts);
#   * the packages Ultralytics needs to run a training job;
#   * the packages the HPO module needs (Optuna and its declared backends).
#
# Provenance: pinned from the independently accepted F1.1 environment
# (environment.yml, Python 3.10), plus the five HPO pins recorded in
# auto_tune/requirements.txt. The root requirements.txt and the stale
# auto_tune/requirements.txt are deliberately NOT merged here: their loose
# bounds and unused entries (gradio, httpx) are not part of the verified
# runtime.
#
# Deliberately absent:
#   * torch / torchvision — installed from the pinned CUDA 12.1 PyTorch wheel
#     index by the Dockerfile, before this file. Adding them here would let pip
#     resolve a CPU wheel over the CUDA build.
#   * pytest, pluggy, iniconfig, exceptiongroup, tomli — test-only.
#   * pyreadline3 — Windows-only.
#   * onnxruntime-gpu — the CUDA execution provider. ONNX export is pinned to
#     device=cpu (see onnx_export_worker.EXPORT_DEVICE) and training runs on
#     torch, so the container only needs the CPU build of ONNX Runtime.
#   * onnxslim — Ultralytics requires it only for ``simplify=True``, and the
#     export arguments are frozen at simplify=False. Adding it would pull
#     ml-dtypes for a path the product never takes.
#
# The F1.2-C ONNX decision (approved 2026-09-21): onnx + protobuf are required
# because the F1.2-A export worker calls onnx.checker / onnx.load, and
# Ultralytics only accepts onnx 1.x (any 1.12 or newer release up to 2.0);
# onnxruntime (CPU) is required so the container can prove the exported graph
# really infers, not merely that the module imports.
