# Auto-Tune Studio 操作工手册（2026-08-21）

## 1. 适用范围

本手册适用于单人、单机、独立部署的 Auto-Tune Studio。系统默认在本机 `127.0.0.1:8000` 提供页面；多人协作和云端密钥托管不属于 Studio 范围。

## 2. 启动与关闭

### 2.1 启动

在 PowerShell 中执行：

```powershell
conda activate auto_tune
Set-Location 'E:\dataprocess_modeltrain\Auto_labeltrain_project'
python -m auto_tune.ui.app
```

浏览器访问：

```text
http://127.0.0.1:8000
```

### 2.2 关闭

回到启动终端并按 `Ctrl+C`。确认终端显示应用已完成关闭后再关闭窗口。

## 3. 首次配置 AI 服务

### 3.1 默认供应商

- 文本诊断与调参决策：DeepSeek。
- 视觉分析：通义千问。
- 高级用户可以填写受安全策略约束的 OpenAI-compatible Endpoint。

### 3.2 获取 API Key

1. 使用客户自己的 DeepSeek/通义千问账号进入供应商控制台。
2. 创建仅供当前 Studio 设备使用的 API Key。
3. 记录 Key 的用途、设备、创建时间和负责人；推荐名称包含设备标识，例如 `studio-workstation-01`。
4. 不要把 Key 发送到聊天群、邮件、工单或截图，也不要写入 `config.yaml`、README、脚本、命令行或数据集目录。
5. Key 通常只在供应商创建时显示一次；准备好后立即在 Studio 中保存。

供应商控制台界面可能随时间变化，以供应商当前官方说明为准。Studio 不负责创建、查看、导出或找回供应商 Key。

### 3.3 保存和测试

1. 打开“项目总览”中的“AI 服务配置”。
2. 在“文本与调参服务”密码框填写 DeepSeek Key。
3. 点击“保存密钥”，选择保存前测试。
4. 成功后应显示“已配置：Windows Credential Manager”，密码框自动清空。
5. 在“视觉服务”用同样方式保存通义千问 Key。
6. 分别点击“测试连接”。
7. 执行一次文本大模型分析和视觉分析，确认真实业务链路有效。

Studio 页面永远不会回显已保存 Key 的原值、前缀、尾号、长度或摘要。

## 4. 升级、换机和重装时是否需要新 Key

### 4.1 同一台机器正常升级

通常不需要重新生成或重新填写 Key。Windows Credential Manager 中的凭据属于当前 Windows 用户，不随项目源码升级被覆盖。

升级后应执行一次“测试连接”。如果 Windows 用户发生变化、凭据被手工删除或系统安全策略清理了凭据，则需要重新配置。

### 4.2 换到另一台机器

新机器必须重新配置凭据，因为 Windows Credential Manager 不会随项目文件、ZIP、Git或配置备份复制。

技术上可以在新机器重复使用原 Key，但客户交付推荐每台机器生成独立 Key，原因如下：

- 单台设备泄漏时可以只吊销该设备 Key；
- 更容易识别调用来源和费用；
- 设备报废或移交时不会影响其他机器；
- 降低同一 Key 在多处传播的风险。

推荐换机步骤：

1. 在供应商控制台为新机器创建独立 Key。
2. 在新机器 Studio 页面保存并测试。
3. 完成真实分析验证。
4. 如果旧机器不再使用，立即在供应商控制台吊销旧机器 Key。
5. 删除旧机器 Studio 中的本机凭据，并按组织要求清理或重装设备。

禁止从旧机器导出明文 Key 再复制到新机器。Studio 本身也不提供 Key 导出功能。

### 4.3 重装 Windows 或更换 Windows 用户

应按新机器处理。Credential Manager 凭据可能无法保留或无法由新用户读取。推荐生成新 Key，而不是依赖旧系统备份恢复秘密。

### 4.4 仅复制项目目录或恢复代码备份

项目目录不包含 API Key。复制完成后页面显示“未配置”属于正常现象，需要在目标机器重新保存凭据。

## 5. Key 轮换与应急处置

出现以下任一情况必须立即轮换：

- Key 曾写入 YAML、脚本、README、日志或截图；
- Key 曾发送到聊天、邮件、工单或公开仓库；
- 设备丢失、报废、转交或账号人员变更；
- 供应商提示异常调用；
- 组织规定的定期轮换时间到期。

轮换步骤：

1. 在供应商控制台创建新 Key。
2. 在 Studio 中选择“替换密钥”，使用新 Key完成保存前测试。
3. 执行一次真实大模型分析。
4. 在供应商控制台吊销旧 Key。
5. 检查本机项目目录、脚本、日志和备份中是否残留明文。

如果确认 Key 已公开泄漏，应优先在供应商控制台吊销旧 Key，再处理本机配置。把旧 Key 移入 Credential Manager不能撤销历史泄漏。

## 6. Linux 与 Docker 部署的凭据说明

### 6.1 当前能力边界

- Windows Studio 已支持 Windows Credential Manager和环境变量。
- 当前 Linux代码只支持环境变量，不支持把 Key从 Studio页面持久化到 Linux Secret Service。
- 当前版本尚未实现 `AUTO_TUNE_TEXT_API_KEY_FILE` / `AUTO_TUNE_VISION_API_KEY_FILE`，Docker Secret文件读取属于后续 S1.3.1 跨平台凭据适配，不能写成已可用能力。

### 6.2 Linux桌面单机

当前使用：

```bash
export AUTO_TUNE_TEXT_API_KEY='在终端安全注入，不写入脚本'
export AUTO_TUNE_VISION_API_KEY='在终端安全注入，不写入脚本'
python -m auto_tune.ui.app
```

不要把 export 命令连同真实 Key写入项目脚本、Shell历史或公开的服务文件。后续正式 Linux桌面版本推荐接入 Secret Service/libsecret；该能力依赖桌面会话，不适合作为无桌面服务器的唯一方案。

### 6.3 Docker与无桌面Linux的后续推荐方案

后续 S1.3.1 计划增加两个只读变量，用于指向由平台挂载的 Secret文件：

```text
AUTO_TUNE_TEXT_API_KEY_FILE
AUTO_TUNE_VISION_API_KEY_FILE
```

目标解析优先级：直接环境变量 → Secret挂载文件 → Windows Credential Manager / Linux Secret Service → 未配置。UI只显示来源和配置状态，不允许查看、覆盖或删除外部管理的 Secret。

计划中的 Docker Compose形式如下（当前版本暂不可直接使用 `_FILE` 变量）：

```yaml
services:
  auto-tune:
    image: auto-tune:latest
    secrets:
      - deepseek_api_key
      - qwen_api_key
    environment:
      AUTO_TUNE_TEXT_API_KEY_FILE: /run/secrets/deepseek_api_key
      AUTO_TUNE_VISION_API_KEY_FILE: /run/secrets/qwen_api_key

secrets:
  deepseek_api_key:
    file: ./secrets/deepseek_api_key.txt
  qwen_api_key:
    file: ./secrets/qwen_api_key.txt
```

实现时必须满足：Secret文件为绝对路径普通文件、禁止符号链接、限制大小、推荐权限 `0600`、不进入镜像层/构建上下文/日志/URL，更新 Secret后重启容器或显式失效凭据缓存。

### 6.4 镜像升级和换机

- 更新同一容器镜像不要求重新生成 Key，只要外部 Secret仍由部署平台挂载。
- 换宿主机或新建部署实例时必须重新注入 Secret；镜像本身不包含 Key。
- 推荐每台宿主机或每个部署实例使用独立 Key，便于单独吊销和费用审计。
- 不要通过 `docker commit`、Dockerfile `ENV`、镜像构建参数或提交到Git的 `.env` 文件保存真实 Key。

## 7. 自定义与本地模型 Endpoint

- 公网自定义 Endpoint 必须使用 HTTPS。
- “允许本地/内网模型端点”默认关闭。
- 只有连接 Ollama、vLLM或企业内网兼容服务时才打开该开关。
- 本机/内网 HTTP端点会显示“传输未加密”警告。
- 禁止在 Endpoint URL中嵌入用户名、密码、Token或查询参数。
- 不确定地址是否可信时不要保存，联系管理员核对。

## 8. 数据集与快照

1. 在“数据集报告”选择或填写 YOLO Detect 数据集目录。
2. 运行数据集分析并确认类别和标签错误已经处理。
3. 创建不可变数据集快照。系统复制训练输入，不移动或改写原始图片与标签。
4. 快照状态必须显示有效后才可启动普通训练或非 dry-run 自动调优。
5. 相同来源和划分参数可复用已有完整快照。
6. 快照损坏时训练会被拒绝；不要手工修改快照中的图片、标签、manifest或 `data.yaml`。

## 9. 训练与分析

1. 在“训练监控”确认模型、epoch、batch和图片尺寸。
2. 启动训练后查看精简日志；需要排障时展开完整日志。
3. 训练完成后在“智能分析”查看 mAP50、mAP50-95、Precision、Recall和诊断。
4. 启用文本/视觉服务时会把结构化指标摘要或选定图片发送给配置的模型服务。
5. 不希望联网时关闭对应 AI 服务；本地数据分析和训练仍可使用。

## 10. 自动调优

1. 先完成至少一次可用训练作为参考运行。
2. 选择 dry-run 可只检查决策、Schema和 Guardrails，不启动真实训练。
3. 非 dry-run 自动调优必须使用校验通过的不可变快照。
4. 大模型只能建议白名单参数，最终执行值必须经过 Guardrails和审计持久化。
5. 在历史详情中核对建议值、实际值、命令、before/after/delta和错误终态。

## 11. 常见问题

### 11.1 页面显示 `credential_missing`

对应服务尚未保存 Key，或当前 Windows 用户无权读取原用户的凭据。进入“AI 服务配置”重新保存并测试。

### 11.2 换机后配置文件存在，但页面显示未配置

这是预期行为。配置文件只保存非敏感设置，Key 不随项目复制。请为新机器生成并保存独立 Key。

### 11.3 连接测试失败

依次检查网络、供应商余额/权限、模型名、Endpoint和 Key状态。错误响应不会显示供应商完整正文；需要进一步排查时使用供应商控制台请求记录。

### 11.4 不小心把 Key写进文件

立即到供应商控制台吊销，生成新 Key并通过 Studio 保存。只从文件删除旧 Key不等于完成轮换。

### 11.5 训练成功但大模型分析失败

训练事实仍然有效。修复 AI 服务连接后重新分析，不要把训练状态改成失败。

## 12. 操作红线

- 不共享、不截图、不导出 API Key。
- 不把真实 `config.yaml`、日志、数据集、权重或训练产物提交 GitHub。
- 不在训练中修改或删除当前快照。
- 不在不可信网络上开启内网 Endpoint或使用明文 HTTP。
- 不把 Studio 的本机单用户模式暴露为多人服务。
