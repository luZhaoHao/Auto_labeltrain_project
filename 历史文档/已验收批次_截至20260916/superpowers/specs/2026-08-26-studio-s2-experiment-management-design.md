# Studio S2.1–S2.4 实验管理扩展设计

**日期**：2026-08-26

**状态**：艾卡已批准

**目标工期**：12–20 人日
**交付方式**：统一规格、连续开发、一次验收和发布；四个内部检查点

## 1. 目标与边界

S2.0 已完成 SQLite 稳定索引。本批把“可查询投影”补成可恢复、可追溯、可诊断和可比较的本地实验管理闭环。JSON 历史、S1.5 运行状态、数据集快照、报告和训练产物继续作为事实来源；SQLite 仍是可重建索引。

明确不做标签、备注、收藏、永久基线/候选/发布标识、归档、批量删除、自动移动或清理产物、Excel 导出和 AI 自动选择最佳实验。比较页中的基线只存在于单次请求，不写入数据库。

## 2. S2.1 对账、重建与启动补录

- 提供只读 `audit`：扫描受控事实入口，输出缺失、多余、状态/指标/数据集关联/产物状态不一致，不修改任何文件。
- 提供显式 `rebuild`：先创建受控备份，在同目录临时数据库完整重建、执行完整性检查后用 `os.replace` 原子发布；失败保留原数据库。
- 启动补录只处理有界的最近记录，补齐可确定的遗漏和产物存在状态，不删除记录、不猜测未知终态。
- 对账和重建结果有稳定 Schema、错误码、时间、计数和有界问题摘要；不泄漏凭据、日志全文或未脱敏本机业务路径。
- 重建并发门禁为单实例；训练可以继续以 JSON/S1.5 落事实，索引写入失败保持非致命，重建结束后再次补录尾部变化。

## 3. S2.2 实验详情、数据集关联与产物可用性

- 详情统一展示 run_id、来源、状态、时间、模型、任务、数据集快照、参数、指标、调优决策/护栏和错误事实。
- 产物清单覆盖报告、审计、results.csv、args.yaml、运行目录、best.pt、last.pt 和快照 manifest；状态为 exists/missing/unregistered/unavailable，不自动移动或删除。
- 数据集详情展示关联实验数量、最近使用、按同一指标口径计算的最佳事实和最近实验；不同任务指标不得混用。
- 打开文件/目录只能使用已登记受控路径和现有安全边界；缺失或越界返回稳定错误，不拼接任意客户端路径。

## 4. S2.3 搜索、排序、分页与数据库诊断

- 实验查询支持名称/模型搜索、dataset/source/status 组合筛选、时间/名称/受支持指标排序。
- 使用稳定分页契约；第一版采用 `limit + offset`，`limit` 为 1–100，默认 25，最大 100，并返回 total/limit/offset/items。
- 搜索转义 LIKE 通配符并全部参数化；排序字段使用服务端白名单，客户端不得传入 SQL 片段。
- 诊断返回 Schema 版本、数据库/WAL 大小、记录数、quick_check、备份数量、最近导入/对账/重建和最近稳定错误码。
- 写操作仅开放 quick_check、WAL checkpoint、手动备份、audit 和 rebuild；全部复用现有 CSRF/origin 门禁。禁止清空数据库和删除历史。

## 5. S2.4 基础实验比较

- 每次选择 2–5 个 run_id，并明确一个 baseline_run_id；输入去重、数量和存在性严格校验。
- 比较身份、模型/任务、数据集快照、参数差异、mAP50/mAP50-95/Precision/Recall、训练时长/epoch、调优建议/护栏/实际参数和产物完整性。
- 相同参数默认折叠；忽略 name/project/save_dir 和下划线内部元数据等运行噪声。
- 缺失指标保持 null；基线为 0 时相对变化为 null；不同数据集快照、任务或指标口径时 `comparable=false` 并给出稳定 warning，仍可展示事实但不得生成优劣结论。
- 只输出“某指标最高、耗时最短、产物最完整”等事实摘要，不返回“最佳模型”或自动训练建议。

## 6. 数据与迁移

- 优先复用 S2.0 Schema v1；确需保存对账/重建运行摘要时新增 Schema v2 正向迁移，禁止改写已发布 v1 语句和 checksum。
- 用户管理信息不进入 Schema。诊断和比较均可由事实投影即时计算，避免为展示重复存储大块 JSON。
- 所有列表有界，所有文件扫描有成员数/容量/时间边界；数据库、备份、WAL、训练产物继续由 `.gitignore` 排除。

## 7. API 最小契约

- `GET /api/local-index/audit`
- `POST /api/local-index/rebuild`
- `POST /api/local-index/checkpoint`
- `POST /api/local-index/backup`
- `GET /api/local-index/diagnostics`
- `GET /api/datasets/{dataset_id}/experiments`
- `GET /api/experiments`：扩展 search/sort/order/limit/offset
- `GET /api/experiments/{run_id}`：扩展详情和产物清单
- `POST /api/experiments/compare`

响应只包含稳定错误码和安全消息。不存在、损坏、锁定、重建进行中、非法查询、不可比较分别使用明确错误或 warning，不伪装空成功。

## 8. UI

- 历史页增加搜索、排序、分页、2–5 条勾选和“比较实验”。
- 详情使用现有页面风格展示数据集、参数、指标、调优事实和产物状态。
- 数据集页增加关联实验摘要和入口。
- 诊断区展示索引健康、备份、对账/重建结果；高风险操作只保留重建，并要求明确确认。
- 所有服务端/文件内容使用安全文本渲染；不引入新前端框架。

## 9. 验收门

- 四个内部检查点各自 TDD 和定向回归，最终完整 pytest 必须通过。
- 真实 1 epoch 普通训练和最小非 dry-run 调优保持 S1.5/JSON/SQLite/报告/results.csv 一致。
- Chromium 验证搜索、分页、详情、关联、诊断、对账、重建和比较；刷新/重连不回归。
- 故障注入覆盖损坏库、锁、备份失败、重建失败、重建并发、尾部漏写、缺失产物和不同快照不可比较。
- Git 白名单提交，不包含数据库、数据集、图片、权重、训练产物、日志、真实配置、凭据或无关工作区文件。

## 10. 后续阶段

S2 完成后进入 S3：YOLOv8 Detect 回归冻结、YOLOv8 Classify 产品闭环和 YOLOv5 Detect 遗留适配。S3 冻结支持矩阵后再进入 S4 Linux适配与产品封装。
