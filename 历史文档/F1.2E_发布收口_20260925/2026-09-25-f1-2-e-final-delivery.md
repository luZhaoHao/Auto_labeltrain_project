# F1.2-E 最终交付收口实施计划

> **执行约束：**本计划由 Codex 主责执行与验收；Claude Code 仅在最终验收发现业务代码缺陷时，按艾卡转发的独立提示词实施返修。计划使用复选框记录进度。

**目标：**把已经完成的 F1.2-A 至 F1.2-D 收敛为可核验、可安装、可追溯且不泄露数据或凭据的 Windows 离线包、Docker 源码交付与 Docker 镜像归档，并完成手册、发布清单和版本提交准备。

**总体方案：**先盘点并清理已经能够明确判定的临时物、旧候选包和重复文档，再冻结同一份源码候选和版本号，随后分别构建 Docker 与 Windows 最终交付物；任何实测都只针对最终候选物，不复用旧镜像或旧轻量 ZIP 的结论。最终事实在交付物通过后回写权威文档，最后由艾卡决定是否提交、推送和删除本机中间镜像。

**技术栈：**Windows PowerShell 5.1、ZIP、Python 3.10、PyTorch 2.5.1+cu121、Docker Desktop Linux Engine、NVIDIA GPU、Docker Compose、SHA-256、pytest、DOCX/LibreOffice。

**规格依据：**`docs/f1_2_windows_docker_onnx_spec_20260918.md`、`docs/development_handoff_20260814.md`、`docs/roadmap_20260814.md`、`docs/implementation_plan_20260814.md`。

## 全局约束

- F1.2-E 不新增业务功能；仅允许修复最终验收发现的 P0/P1 缺陷及对应测试。
- Windows 最终包必须完全离线安装，不依赖用户自行下载 Python、Conda、PyTorch 或普通 wheel。
- Docker 同时交付可自行构建的源码文件和可直接导入的镜像归档；正式运行必须申请 NVIDIA GPU，不提供 CPU 训练回退。
- Docker 镜像中不得包含密钥、真实配置、数据集、权重、数据库、日志或训练结果。
- Windows ZIP 中不得包含真实 `config.yaml`、密钥、用户数据、训练结果或开发测试文件。
- Python 与 pytest 固定使用 `D:\Program Files\anaconda3\envs\auto_tune\python.exe`，先记录解释器和版本。
- Docker 服务只能由艾卡开启；Codex 不启动、重置或迁移 Docker Desktop。
- 未经艾卡单独确认，不删除镜像、容器、卷、依赖、构建包或工作区文件。
- `docs/` 仅保留当前权威文档；旧版移入 `历史文档/`，永久删除须再次确认。
- 不创建包含数据集、权重或训练结果的工作树或项目副本。
- 最终提交和推送必须在艾卡确认交付方向后进行，目标仅为已批准的公开仓库。

## 重点复核风险

1. **磁盘峰值：**Docker 镜像、镜像归档、离线依赖和 Windows ZIP 同时存在时不得占满 E 盘；每个大文件步骤前后都记录剩余空间。
2. **候选漂移：**文档、Docker 镜像和 Windows ZIP 必须对应同一源码状态；构建后不得静默修改业务代码。
3. **离线真实性：**Windows 安装测试必须阻断网络或使用安装器的离线契约证明零下载，不能用开发机 Conda 代替私有运行环境。
4. **持久化与回滚：**升级、卸载、Docker 重建后，用户配置和 SQLite 数据必须按约定保留；失败不得破坏已有可用安装。
5. **发布污染：**Git、真实配置、密钥、数据、权重、日志、数据库、临时目录和测试产物不得进入交付物或 Git 提交。

## F1.2-E 完成判定

只有同时满足以下条件，才能宣布 F1.2-E 和整个 F1.2 完成：

1. 最终 Docker 镜像及其归档、源码构建方式全部通过 GPU 实测。
2. 最终 Windows 完全离线 ZIP 从解压目录完成真实安装与 GPU 核心流程。
3. 正常训练、HPO、LLM、ONNX 在最终候选上均有可追溯证据。
4. 两份手册截图、文字和 DOCX 版式复核完成。
5. 权威文档同步，旧文档按规则归档。
6. 完整回归和敏感信息检查通过，无未处置 P0/P1。
7. 工作区分类与发布清单经艾卡确认。
8. 提交与推送仅在艾卡明确批准后执行。
