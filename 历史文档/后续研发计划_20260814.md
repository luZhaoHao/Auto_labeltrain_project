# Auto-Tune 后续研发计划书（2026-08-14）

## 1. 总体目标

建设一套同时支持本地单机和在线多人使用的视觉模型研发系统，覆盖数据质量分析、训练结果诊断、超参数自动调优、任务与模型版本扩展、受控模型结构实验，以及与 CVAT 的解耦集成。

系统分为四个稳定领域：

```text
数据域：数据集、快照、质量报告
训练域：训练任务、执行参数、GPU/进程、产物
分析域：数值事实、规则诊断、LLM/视觉解释
实验域：超参数实验、结构实验、指标对比、最佳模型
```

## 2. 全局原则

- 当前一期只自动修改超参数，不调整模型结构。
- 模型结构解析和结构自调整在后续同一期完成。
- LLM 只生成候选决策，不能直接生成或执行命令。
- Python 产生事实，规则系统进行确定性判断，LLM负责解释与有限决策。
- 数据原件不可变；训练使用可追溯快照。
- 所有训练必须记录建议参数、校验参数、实际参数和指标变化。
- 本地与在线共享领域模型，存储、认证和调度通过接口替换。
- CVAT 负责标注与数据版本，Auto-Tune 负责分析、训练和模型交付。

## 3. 阶段 A0：当前闭环可靠性加固

### A0.1 安全基线

- 撤销并轮换仓库中的 DeepSeek/Qwen 密钥；
- 配置改为环境变量或本地私密文件；
- 正式流程以选择受控目录为准，不再建设 ZIP 上传体验；
- 代码中遗留的 ZIP 兼容 API 保持安全解压，确认无调用方后再单独评估停用；
- 文件夹浏览限制允许根目录；
- 数据集划分不再移动原始文件，改为快照或临时目录原子生成。

### A0.2 Module B 事实层修复

- 正确读取 `train_analyzer` 配置段；
- 修复 Early Stopping 数据接口；
- 修复 Plateau、Stale 和震荡窗口算法；
- 统一缺失值语义，缺失指标不得默认为 0；
- 将视觉结论标记为假设，并与数值事实做一致性检查；
- 后续改为基于预测框与 GT 的 IoU 匹配生成 FP/FN/定位错误。

### A0.3 超参数注册表

建立单一参数注册表，描述：

- 名称、类型、范围、默认值；
- 是否允许 LLM 修改；
- 所属任务和 YOLO 版本；
- CLI 参数名；
- 参数组和依赖关系；
- UI 展示与说明。

Prompt、Guardrails、执行器和 UI 必须从同一注册表读取。

### A0.4 LLM 决策与 Guardrails

- 校验 LLM JSON 结构、字段类型、参数白名单和修改数量；
- `hyperparameter_changes` 与 `training_overrides` 统一验证；
- Guardrails 输出唯一可执行的 sanitized 参数；
- 处理 `optimizer=auto` 与 `lr0/momentum` 冲突；
- 正常模式每轮最多修改 1–3 个相关参数；
- 空修改仅在 `keep_params` 动作下合法；
- API 失败、JSON 错误或非法参数时不得启动训练。

### A0.5 执行审计和实验反馈

每轮记录：

```text
参考训练与原始参数
LLM 原始响应
候选修改
护栏调整
实际训练参数
实际命令
训练前指标
训练后指标
指标差值
探针结论
任务状态和错误
```

写入采用原子文件；阶段 B 可迁移到数据库。

### A0.6 执行与 UI 闭环

- 使用当前 Python 环境可定位的 YOLO 入口，消除 PATH 偶然性；
- 训练前完成环境、CUDA、模型、数据 YAML 校验；
- 训练完成后自动解析 `results.csv`、刷新 KPI、运行 Module B；
- 普通训练和自动调优统一进入历史记录；
- 默认仅显示 epoch、loss、Precision、Recall、mAP；完整日志折叠显示；
- 页面展示“AI建议 → 护栏值 → 实际值”。

### A0.7 测试

- Module C 纳入正式 pytest；
- 覆盖越界、类型错误、未知参数、override 绕过、优化器冲突；
- Loop 测试 mock LLM 和训练进程；
- 完整 pytest 后运行一次 `epochs=1` 冒烟训练；
- 验证审计参数、`args.yaml` 和命令一致。

**A0 验收：** 任何进入 YOLO 的参数都可追溯且经过验证，界面、报告、审计和实际命令一致。

## 4. 阶段 A1：任务/版本适配框架

- 定义 `TaskAdapter`：detect、segment、obb、classify；
- 定义 `ModelAdapter`：YOLOv8、YOLO11、后续经验证的 YOLO26、YOLOv5；
- 适配器负责模型目录、命令构造、结果列映射、评分公式和参数注册表；
- UI 按任务和版本过滤合法模型；
- 首先保持 YOLOv8 Detect 回归，再接 YOLO11 Detect；
- YOLO26 在确认官方支持和当前 Ultralytics 兼容后接入。

**验收：** 同一训练领域接口可运行 v8/v11 Detect，报告字段归一化且旧流程无回归。

## 5. 阶段 A2：Linux 与部署基线

- 创建 Linux 环境文件和启动/测试脚本；
- 按 CUDA 版本安装匹配的 PyTorch；
- 清理 Windows 硬编码路径和 GBK 假设；
- 文件浏览器适配 Linux 根目录和用户目录；
- 增加 `/api/health` 与 `/api/readiness`；
- 记录 Python、Ultralytics、Torch、CUDA、GPU 信息；
- 使用受控 host/port，局域网模式明确安全边界。

## 6. 阶段 A3：本地交互体验

- 通过文件夹浏览器选择服务器上的受控数据目录；
- 展示目录校验进度、失败原因和重新分析；
- 首页卡片响应式布局；
- 统一训练、分析和调优状态；
- 历史记录支持普通训练、调优和报告筛选；
- 中英文案完整、错误信息面向操作人员。

## 7. 阶段 B：在线多人平台

### B1 数据库和领域仓储

- 用户、数据集、快照、训练任务、训练事件、报告、产物、GPU 租约；
- 本地 SQLite 可用于开发，正式部署建议 PostgreSQL；
- 数据库迁移、索引、备份和恢复；
- Repository 接口替换一期 JSON 实现。

### B2 用户、权限和数据隔离

- 注册/登录、角色和会话；
- 每个 API 进行 owner/role 校验；
- 用户空间、磁盘配额、产物生命周期；
- 防止路径穿越、越权读取和下载；
- 管理员只能通过审计接口访问跨用户资源。

### B3 独立训练 Worker 与 GPU 调度

- Web API 不直接持有训练进程；
- 状态机：queued/preparing/running/analyzing/completed/failed/cancelled；
- 单任务独占单卡，数据库原子租约；
- GPU 显存、温度、利用率采集；
- 任务取消、超时、孤儿进程清理；
- 服务重启后对账 PID、Checkpoint、数据库状态；
- 支持失败重试和从合法 Checkpoint 恢复。

### B4 SSE 恢复和历史

- 训练事件持久化并带递增游标；
- EventSource 重连从最后游标继续；
- 历史任务、指标、参数和产物可查询；
- 多训练对比与导出；
- 日志分页，避免一次加载完整日志。

### B5 部署与运维

- Nginx/HTTPS、CORS/CSRF、上传限额；
- 健康检查、指标监控和结构化日志；
- 容量预警、备份、恢复演练；
- 依赖、镜像和模型权重版本固定。

**阶段 B 验收：** 多用户资源隔离、多人排队、GPU 不重复分配、重启可恢复状态、历史可追溯。

## 8. 阶段 C1：任务类型与旧版本扩展

### 分割

- Module A 解析多边形标签并派生 bbox/面积统计；
- Module B 映射 mask 和 box 指标；
- 注册 seg 模型和任务参数；
- 单独评分，不混用 Detect 最佳模型。

### OBB

- 支持四点/角度格式和旋转框几何统计；
- 结果指标与可视化单独适配；
- 增加角度分布、长宽比和方向偏置分析。

### 分类

- 支持按类目录的数据布局；
- 指标改为 top1/top5、宏平均召回等；
- 重写评分和诊断规则；
- 不复用目标检测错误类型。

### YOLOv5

- 使用独立命令适配器；
- 映射不同 results 列和 loss 名称；
- 明确依赖和权重兼容边界。

## 9. 阶段 C2：模型结构解析与受控结构自调整

该阶段作为独立一期，同时交付结构解析和结构调整。

### C2.1 结构解析器

- 读取模型 YAML 和已实例化模型；
- 输出 Backbone、Neck、Head、层连接、通道、Stride；
- 统计参数量、FLOPs、显存估算、预训练权重匹配率；
- 生成结构化 JSON 和人类可读结构图；
- 保存结构指纹，保证实验可追溯。

### C2.2 模块注册表

- 只注册经过测试的 Attention、Neck、卷积和 Loss 模块；
- 描述输入输出通道、支持任务、版本和显存成本；
- 禁止任意 import、任意 Python 和任意 YAML tag。

### C2.3 结构变体生成

- 基于合法模板生成变体；
- 兼容性、张量尺寸、参数量和显存预检；
- 支持 baseline、单变量和小组合消融；
- 失败自动回退，不覆盖已有最佳模型。

### C2.4 结构决策 Agent

- 与超参数 Agent 分离动作空间；
- 输入数据特征、训练瓶颈、结构事实和资源预算；
- 输出注册表中的有限动作；
- 每轮优先改变一个结构维度；
- 使用独立实验评分和人工审批开关。

**阶段 C2 验收：** 每个结构变体可解释、可复现、可回退，并能通过受控消融说明收益来源。

## 10. 阶段 C3：CVAT 解耦集成

- CVAT 固化 Project/Task 数据快照并导出；
- Auto-Tune 接收快照、类别映射和来源版本；
- 任务状态、指标、日志和模型产物通过 API 返回；
- 模型经审批后注册为 CVAT 自动标注能力；
- 使用服务 Token/OAuth 和最小权限；
- CVAT 不直接控制训练子进程，Auto-Tune 不直接修改 CVAT 标注；
- 训练队列复用阶段 B，不重复建设。

## 12. 总体验收指标

- 参数审计一致率 100%；
- 非法 LLM 参数进入训练命令的数量为 0；
- 普通训练与调优任务均可追溯；
- 多用户越权测试全部阻止；
- GPU 同时分配冲突数量为 0；
- 服务重启后任务状态可对账；
- 任一模型产物可定位到数据快照、参数、代码/依赖版本和实验记录；
- 结构实验必须有 baseline 和消融证据。
