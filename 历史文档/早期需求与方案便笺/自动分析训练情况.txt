要设计一套极致节省 Token 且分析极其精准的 AI 诊断方案，我们需要采取 “文本优先（Text-First）、轻量解析（Code-Parsing）、按需调用图片（Vision-on-Demand）” 的分层调阅策略。
一、 文件“分类与剪枝”：哪些可以忽略或替代？YOLOv8 训练生成的这些文件，大部分可以被简单的 Python 脚本提取成极小的文本数据，完全不需要消耗视觉 Token：
1. 绝对不需要给 MLLM 看图的文件（完全忽略图片，改用代码解析）
results.png 【忽略图片】原因：YOLOv8 训练时同时会生成一个 results.csv！Python 代码读取这个 CSV 只需要 1 毫秒，就能精确提取最后一个 Epoch 的 box_loss、cls_loss、dfl_loss 以及 mAP50、mAP50-95 的数值和变化趋势。用代码转成文本只有几十个 Token，而图片需要上千 Token 且 MLLM 读数还不一定精准。
P_curve.png / R_curve.png / F1_curve.png / PR_curve.png  【忽略图片】原因：这 4 张曲线图的核心结论其实都收录在 PR_curve.png 和 F1_curve.png 里，而且具体数值在 results.csv 和模型验证输出里都有结构化文本。如果确实想分析 F1 最优置信度阈值，用代码去算曲线峰值远比让 MLLM “用眼睛看”更准。
train_batch0.jpg ~ train_batch2.jpg  【直接忽略】原因：这只是训练前期的 Data Augmentation（如 Mosaic）可视化快照，用于人工检查数据增强效果。在自动分析训练收敛情况时，它们属于静态参考，对诊断训练瓶颈几乎没有帮助。
labels.jpg / labels_correlogram.jpg  【忽略图片】原因：这是数据集标注框的分布图，属于“数据集分析”范畴，而非“训练状态分析”。如果一定要分析，直接解析 YAML 和标签文本文件的长宽比统计即可。

2. 核心精简后：真正有价值的输入（极简组合）经过剪枝后，诊断“训练情况”只需要以下核心文件：
文件名,        格式/处理方式,        核心分析目的
args.yaml,  纯文本,读取当前训练配置（超参数、Batch Size、初始学习率等）
results.csv (附带文件),纯文本（计算后的趋势指标）,  诊断模型是否欠拟合、过拟合、梯度爆炸或早停
confusion_matrix_normalized.png,图片  （多模态可选）  ,诊断哪些类别发生严重混淆、背景误检率（Background FP）
val_batchX_labels.jpg vs pred.jpg,图片对 （多模态按需调阅） ,诊断模型具体的错误类型（漏检、定位偏移、误检）

二、 架构设计：极致节省 Token 的“三阶诊疗”工作流
[训练结束/异常触发]
       │
       ▼
【一阶段：Python 代码轻量诊断器】
 ├── 解析 results.csv (提取 Loss 趋势、mAP 峰值)
 ├── 解析 args.yaml (读取超参)
 └── 计算指标异常度 (是否过拟合？mAP 是否达标？)
       │
       ├─────────────────────────────────┐
       ▼ (正常/轻度异常)                  ▼ (严重异常/性能瓶颈)
【二阶段：纯文本 LLM 诊断】        【三阶段：按需调用 MLLM 视觉诊断】
 ├── 输入：结构化 JSON 数据        ├── 输入：文本 JSON + 混淆矩阵图 + 错检 Crop 图
 └── 输出：超参微调建议            └── 输出：深层归因与综合改进策略

 第一阶段：Python 脚本做“血检”（0 Token 消耗）
训练结束后，由 Python 脚本先对 results.csv 进行数据分析，生成一份结构化的 JSON 诊断报告：
{
  "epochs_completed": 100,
  "best_mAP50": 0.82,
  "final_box_loss": 0.045,
  "is_overfitting": true,  // 监控到 val_box_loss 在最后 20 个 epoch 持续上升
  "is_converged": true,    // train_loss 已平稳
  "worst_performing_class": "crack" // 根据验证集统计出指标最差的类别
}

第二阶段：纯文本 LLM 做出初步判断（~200 Token）
把上面的 JSON 和 args.yaml 拼接成 Prompt 传给纯文本大模型（如 GPT-4o-mini 或 DeepSeek-V3）。

LLM 思考逻辑：“我看到 is_overfitting 为 true，且 val_box_loss 在上升，这说明模型在回归任务上过拟合了。当前 weight_decay 是 0.0005，mosaic 是 1.0。”

评估决策：如果此时指标已经达到预期，直接输出超参调整建议，终止流程，无需消耗任何视觉 Token。

第三阶段：触发“视觉会诊” (Vision-on-Demand)（仅消耗 ~500-1000 Token）
当二阶段发现严重异常（比如：某些类别 mAP 接近 0，或者出现严重过拟合），触发视觉诊断，且只调阅以下特定的裁剪/图片：

只发 confusion_matrix_normalized.png（归一化混淆矩阵）：

为什么只发归一化版？ 原版 confusion_matrix.png 显示的是绝对数量，受类别不平衡影响极大；归一化版显示的是百分比，大模型一眼就能看出“类别 A 有 40% 被错判成了背景（漏检）”。

生成并裁剪“对比差值图”（Crop Diff）：

绝对不把整个 val_batch0_pred.jpg（包含十几个小图的大图）发过去。

用 Python 代码比对 val_batch0_labels.jpg 和 val_batch0_pred.jpg，自动把 IoU 低于 0.3 或者置信度很低（False Positive / False Negative）的小局部图（224x224 像素）裁剪出来拼接在一起发给 MLLM。

MLLM 只需要看这张小裁剪图，就能给出极具价值的专家意见：“我看了一下错检样本，模型把光照反光误判为了裂纹，建议增加 hsv_v（亮度数据增强）并微调 cls 损失权重。”
